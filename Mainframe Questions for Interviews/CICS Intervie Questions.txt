### **General CICS Concepts**
1. **What is CICS?**  
   - CICS (Customer Information Control System) is a transaction processing system for IBM mainframes.

2. **What are the main components of CICS?**  
   - Programs, Transactions, Files, Databases, and Terminals.

3. **What is a CICS transaction?**  
   - A CICS transaction is a unit of work initiated by a transaction ID.

4. **What is the purpose of the PPT in CICS?**  
   - The Program Processing Table (PPT) maps programs to their attributes in CICS.

5. **What is the difference between pseudo-conversational and conversational programming in CICS?**  
   - Pseudo-conversational programming releases resources between user interactions, while conversational programming holds resources.

---

### **CICS Commands**
6. **What is the purpose of the `EXEC CICS SEND` command?**  
   - It sends data to the terminal.

7. **What is the purpose of the `EXEC CICS RECEIVE` command?**  
   - It receives data from the terminal.

8. **What is the difference between `LINK` and `XCTL` in CICS?**  
   - `LINK` returns control to the calling program, while `XCTL` transfers control without returning.

9. **What is the purpose of the `EXEC CICS START` command?**  
   - It initiates a new transaction.

10. **What is the purpose of the `EXEC CICS RETURN` command?**  
    - It ends the current transaction and returns control to CICS.

---

### **File Handling**
11. **How do you read a record from a VSAM file in CICS?**  
    - Use the `EXEC CICS READ` command.

12. **How do you write a record to a VSAM file in CICS?**  
    - Use the `EXEC CICS WRITE` command.

13. **What is the purpose of the `DELETE` command in CICS?**  
    - It deletes a record from a VSAM file.

14. **What is the difference between `READ` and `READNEXT` in CICS?**  
    - `READ` retrieves a specific record, while `READNEXT` retrieves the next sequential record.

15. **How do you handle file errors in CICS?**  
    - Use the `RESP` and `RESP2` options to capture error codes.

### **CICS Maps**
16. **What is a BMS map in CICS?**  
    - A BMS map defines the screen layout for terminal interactions.

17. **What is the purpose of the `DFHMSD` macro in CICS?**  
    - It defines the mapset attributes.

18. **What is the difference between `DFHMDI` and `DFHMDF` macros?**  
    - `DFHMDI` defines the map, while `DFHMDF` defines individual fields.

19. **What is MDT in CICS maps?**  
    - The Modified Data Tag (MDT) indicates whether a field has been modified by the user.

20. **How do you handle screen input and output in CICS?**  
    - Use `EXEC CICS SEND` for output and `EXEC CICS RECEIVE` for input.

### **CICS Transactions**
21. **What is the purpose of the TCT in CICS?**  
    - The Terminal Control Table (TCT) maps terminals to their attributes.

22. **What is the difference between synchronous and asynchronous transactions in CICS?**  
    - Synchronous transactions wait for completion, while asynchronous transactions do not.

23. **How do you terminate a transaction in CICS?**  
    - Use the `EXEC CICS RETURN` command.

24. **What is the purpose of the `ABEND` command in CICS?**  
    - It terminates a transaction abnormally.

25. **How do you restart a transaction in CICS?**  
    - Use the `EXEC CICS START` command with appropriate parameters.

1.What is a mapset?

Mapset is a collection of maps which are linked edited together to form a load module. 
It should have a PPT entry. It can have names from 1 to 7 chars.

2. What are the differences between an EXEC CICS XCTL and an EXEC CICS LINK command?

The XCTL command transfers the control to an application program at the same logical level and it does not 
expect the control back, while the LINK command passes the control to an application program at the next logical 
level and expects the control back.

3. Into which table is the terminal id registered?

What is meant by PPT and what are its uses?

PPT (Program Processing Table): – It consists of a list that has all the names of the programs in it along with maps. 
Furthermore, it tells us whether the version that is absolutely recent as available as a program in CICS or a
 fresh copy of the program is supposed to be loaded.

4. Differentiate between PCT and FCT.

PCT stands for Program Control Table and it has a complete list of transaction identifiers that are paired to respective corresponding programs.
FCT, on the other hand, stands for File Control Table has a complete list of all the files that have been used by CICS along with their status and record length.


5. Give the definition of COMMAREA ?

COMMAREA is commonly termed as a communication area as it happens to be for temporary storage area. 
It is used as a passing medium for data amongst multiple programs that are loaded by a set of transactions or a 
particular transaction.


TSQ & TDQ – Difference & when will you go for what?

Temporary Storage Queue (TSQ)

Purpose: Used for temporary storage of data that can be accessed multiple times during the life of a transaction or session.
Characteristics:
Data can be read and written multiple times.
Data is retained until explicitly deleted or the transaction/session ends.
Can be used for intra-transaction communication.
Can be dynamically created and deleted.
Supports random access to data.

Transient Data Queue (TDQ)
Purpose: Used for sequential processing of data, typically for communication between different transactions or systems.
Characteristics:
Data is read once and then deleted (destructive read).
Data is retained until read.
Typically used for inter-transaction communication.
Can be predefined (in CICS tables) or dynamically created.
Supports sequential access only.


When to Use TSQ
When you need to store data temporarily and access it multiple times within the same transaction or session.
When you need random access to the stored data.
When you need to share data between different parts of a transaction.

When to Use TDQ
When you need to pass data sequentially between different transactions or systems.
When you need to ensure that data is processed once and then discarded.
When you need to trigger other transactions or batch jobs based on the data.

The Resource Control Table (RCT) is a critical component in CICS (Customer Information Control System) when integrating with DB2. Here are the key points highlighting its importance:





Importance of RCT in CICS?
Authorization Control:

The RCT defines which DB2 plans can be executed by which CICS transactions.
It ensures that only authorized transactions can access specific DB2 resources, enhancing security.
Resource Management:

The RCT maps CICS transactions to DB2 plans, allowing efficient management of DB2 resources.
It helps in controlling the allocation and usage of DB2 plans, ensuring optimal resource utilization.
Performance Optimization:

By defining the relationship between CICS transactions and DB2 plans, the RCT helps in optimizing the performance of database operations.
It allows for better tuning and management of DB2 access paths, leading to improved transaction processing times.
Transaction Isolation:

The RCT helps in isolating different transactions by mapping them to specific DB2 plans.
This isolation ensures that transactions do not interfere with each other, maintaining data integrity and consistency.
Simplified Administration:

The RCT provides a centralized way to manage the interaction between CICS and DB2.
It simplifies the administration of DB2 resources within the CICS environment, making it easier to configure and maintain.


Difference between Symbolic & Physical map?

Symbolic Map
Definition: A symbolic map is a COBOL copybook that contains the data structures corresponding to the fields on the screen. It is used by the application program to interact with the screen data.
Purpose: Provides a way for the COBOL program to reference screen fields symbolically.
Contents: Contains field definitions, attribute bytes, and length fields for each screen field.
Usage: Included in the COBOL program using the COPY statement.

Physical Map
Definition: A physical map is a load module created by the CICS map assembler. It defines the actual layout of the screen, including field positions, lengths, and attributes.
Purpose: Used by CICS to control the display and formatting of the screen.
Contents: Contains the screen layout, field positions, lengths, and attributes.
Usage: Loaded into CICS and referenced by the transaction to display the screen.
Example: Not directly visible in the COBOL program, but referenced by the mapset name.


What is MDT? Ways of setting & resetting MDT?

Ways of Setting MDT
Automatic Setting by User Input:

When a user modifies a field on the screen, the MDT for that field is automatically set by CICS.
Explicit Setting in the Program:

You can explicitly set the MDT in your COBOL program using the ATTRB option in the SEND MAP command.

Few error codes, you faced in CICS development?

Common CICS Error Codes
AEI0: Program not found

Cause: The specified program is not defined in the CICS region.
Solution: Ensure that the program is defined in the CICS region using the CEDA DEFINE PROGRAM command.

AEI2: Transaction not found

Cause: The specified transaction is not defined in the CICS region.
Solution: Define the transaction using the CEDA DEFINE TRANSACTION command.
AEI9: Map not found

Cause: The specified map is not defined or not available in the CICS region.
Solution: Ensure that the mapset is correctly defined and available in the CICS region.

AEIV: Invalid EXEC CICS command

Cause: Syntax error or invalid parameters in an EXEC CICS command.
Solution: Review the syntax and parameters of the EXEC CICS command and correct any errors.
AEIP: Program load failed

Cause: The program could not be loaded, possibly due to a missing or corrupted load module.
Solution: Verify that the load module exists and is not corrupted. Recompile and link-edit the program if necessary.

AEY7: Security violation

Cause: The user does not have the necessary authorization to perform the requested action.
Solution: Check the user's security profile and ensure they have the required permissions.

AEY9: Resource not available

Cause: A required resource (e.g., file, queue) is not available.
Solution: Ensure that the resource is correctly defined and available in the CICS region.

AEZC: Deadlock detected

Cause: A deadlock situation has been detected.
Solution: Review the transaction logic to identify and resolve potential deadlock conditions.

AEZ0: Storage violation

Cause: A program attempted to access storage outside its allocated area.
Solution: Review the program logic to ensure it does not access memory outside its allocated area.

AEY8: Task abend

Cause: The task has abended due to an unspecified error.
Solution: Review the abend dump and error logs to identify the cause of the abend and correct the underlying issue.
